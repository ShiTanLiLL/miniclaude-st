# 课程规划：learn-claude-code 复现课程

> Agent 内部规划文档。 learners 看的是 `教案/课程总览.md`，本文件是教师侧的执行计划。

## 设计决策

### 决策 1：尊重原项目 17 课结构（Prompt 1.3）

原项目本身就是教学项目，17 课（s01→s17）由浅入深、边界清晰，Git 与 README 都按教学步骤组织。
→ **不强行重新切分**，复现课程按 s01→s17 顺序推进，追加第 18 课作为"未覆盖内容导航"收尾，共 18 课（符合 10-20 课偏好）。

### 决策 2：复现采用"累积式代码包"，不是"每课独立脚本"

原项目每课一个自包含 code.py（s15 达 3326 行，大量复制前序代码）——那是"每章独立可读"的取舍。
复现项目改为**一个持续生长的 Python 包 `mini_claude/`**：

- 每课 = 一次 PR 规模的增量（新增/修改若干模块）+ 配套教案 + 测试；
- Git 历史即课程演进记录（满足 Prompt 5.1）；
- 每课的"增量代码"天然聚焦，学习者只需读 diff；
- 第 15 课从"总装"变成"查漏补缺 + 整机检修"（原 s15 确实新增了 error recovery、ConsoleBroker、transcript 等真内容，不冲突）；
- 代码总量控制在可读范围（目标 ~3000-4000 行，远小于原 17k，可读性优先于完整性）。

### 决策 3：双轨验证

- **离线测试**（每课必做）：借鉴原项目 tests/ 的 FakeClient 模式，pytest 驱动完整流程断言，不需要 API key；
- **在线体验**（每课给出步骤）：`python -m mini_claude` REPL，学习者自己配 .env 后可真实对话。

### 决策 4：环境

- uv 建虚拟环境（本机系统 Python 3.8 太老，原项目代码需 3.10+；uv 可自动拉取新 Python）；
- 依赖仅 anthropic / python-dotenv / pyyaml / pytest，按课逐步引入（第 1 课只装前两个）；
- API 配置沿用原项目约定（ANTHROPIC_API_KEY / MODEL_ID / 可选 ANTHROPIC_BASE_URL），兼容国产厂商。
