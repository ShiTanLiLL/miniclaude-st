## 一句话定位

learn-claude-code 是一个**教学项目**：用 Python 从零复现 Claude Code 这类编码 Agent 的"Harness（运行环境/缰绳）"，共 17 课（s01→s17），每课只围绕一个固定的 Agent Loop 增加一种机制。

## 核心理念（README 开篇反复强调）

- **智能来自模型，不来自编排代码**。Agent 产品 = 模型（司机）+ Harness（车辆）。
- 反对的路线：用 if-else / 节点图 / 提示词瀑布把 LLM API 调用串起来（"壳脚本自命不凡"）。
- Harness 的组成：Tools（工具）+ Knowledge（知识）+ Observation（观察）+ Action（动作接口）+ Permissions（权限边界）。
- 核心模式就一个循环：`LLM(messages) → 有 tool_use？→ 执行 → 结果塞回 messages → 再来`，直到模型不再调用工具。**循环是常量，机制是变量。**

## s15 组件在循环中的位置（最终架构的"总装图"，复现第 15 课的对照）

| 位置 | 组件 |
|---|---|
| 用户输入前后 | UserPromptSubmit hooks |
| LLM 前 | cron queue / background notifications / compaction pipeline / memory+skills+MCP 组装 system prompt |
| LLM 调用时 | error recovery（429/529 重试、max_tokens 升级、reactive compact） |
| 工具执行前 | PreToolUse hooks + permission |
| 工具分发 | assemble_tool_pool（内置 + MCP 动态工具） |
| 工具执行时 | background dispatch（daemon thread + 占位结果） |
| 工具执行后 | PostToolUse hooks |
| 停止时 | Stop hooks |

## 技术栈与运行环境

- 语言：Python（原项目代码用 `str | None` 等 PEP 604 语法，需 **3.10+**；本机系统 Python 是 3.8.10，但 `uv` 可用 → 复现项目用 uv 建虚拟环境）
- 依赖：`anthropic` SDK（messages.create / tools / tool_use blocks）、`python-dotenv`、`pyyaml`（skills frontmatter）
- API：ANTHROPIC_API_KEY + MODEL_ID；可选 ANTHROPIC_BASE_URL 接兼容厂商（GLM/Kimi/DeepSeek/MiniMax）
- **无数据库、无 Docker**：所有持久化都是本地文件/目录（.tasks/、memory/、journal、worktree）
- 每课 code.py 是独立可运行脚本（REPL 交互），重复包含前序代码 —— 这是原项目的"每章独立可读"取舍

## 测试策略（复现项目离线验收的关键参考）

原项目 tests/ 用 **FakeClient 模式**：
- 用 `SimpleNamespace` 伪造 `response.content`（text block / tool_use block）；
- 用 `FakeMessages.create(**kwargs)` 按脚本吐出预设响应、记录调用参数；
- 这样不花 API key 就能驱动 agent_loop 走完整流程做断言。
- 复现项目采用同样思路：每课配 pytest 离线测试 + 手动 REPL 体验双轨验证。

## 值得注意的演化关系（课程叙事的主线）

1. s02 说"加工具只加一行"（查表分发）→ s04 把策略从循环里搬出去（hooks）→ s15 把所有机制装回同一个循环。
2. s03 的权限检查先在循环里 → s04 移进 PreToolUse hook → s14 MCP 工具的权限由宿主配置决定。
3. s05 的 TodoWrite（会话内清单）→ s10 的 Task System（磁盘持久化 + 依赖图 + 认领）→ s13 的团队基于任务图协作。
4. s06 的子代理（一次性）→ s13 的常驻队友（有收件箱、能等任务）。
5. s08 压缩是"腾上下文"，s09 记忆是"跨会话搬家"，两者互补：一个管短期空间，一个管长期时间。
6. s17 的 goal gate 是 s04 Stop hook 思想的终极应用：停止也要被审查。
