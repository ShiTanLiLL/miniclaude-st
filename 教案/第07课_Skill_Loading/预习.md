# 第 7 课预习 · 知识要按需上桌，别一次全糊脸上

> 前两课治好了"步骤漂移"和"上下文污染"。这节课的问题更隐蔽，但一样烧钱——先看账单。

## 一、下节课要解决什么问题？

假设我们想让 Agent 会做代码评审。最直接的做法：把 157 行的《评审手册》全文塞进 SYSTEM 提示词。问题来了——**这 157 行每次调用模型都要跟着出门**：用户问"帮我跑个测试"要背着它，问"现在几点"也要背着它。SYSTEM 是每轮都要付的固定开销，塞的越多，每次调用越贵、越容易把真正要紧的指令挤到模型注意力的角落里。一本用不上的书，比没有书更占桌子。

下节课学 Claude Code 的漂亮折中：**两级加载**。启动时只把"有哪些技能"扫出来——每个技能一行"`名字: 一句话描述`"，这几行常驻 SYSTEM，便宜得可以忽略；模型自己判断某条技能用得上，再调 `load_skill(名字)` 工具，把整份说明**作为工具结果**拉进对话——只在需要的那次对话里花这一笔钱。**目录常驻，正文按需**，就像图书馆：卡片目录永远摆在那，书是你去借的。

## 二、三个课前小知识

- **YAML frontmatter**：Markdown 文件头部用两行 `---` 包起来的一小块结构化数据，`name: xxx` 一行一条。我们项目的文档文化就是从这开始养起来的——技能的"名片"（名字+描述）写在头部，正文才是"内脏"。解析它用的是 **pyyaml**，课程第一个"正经"第三方库（前六课全是标准库，其实一直在忍着）。
- **目录也是一种提示词**：注意技能描述的写法——"Use when user asks to review code..."——它不仅要说明"这是什么"，还要说明**什么时候该用它**。目录的质量直接决定模型会不会在正确的时机 load 正确的技能。以后你自己写技能，一半功夫要花在描述上。
- **加载进对话 ≠ 加载进 SYSTEM**：load_skill 的结果作为 tool_result 进入**当前这轮对话**，模型这一轮"读过"它。它不会永远驻留——这既是特性（不占长期开销）也是限制（下轮对话还要再 load）。第 8 课讲上下文压缩时，你会看到这个特性怎么救我们的命。
