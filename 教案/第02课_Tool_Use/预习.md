# 第 2 课预习 · 给只会抡锤子的 Agent 配个工具箱

> 上节课我们的 Agent 只有 bash 一把锤子。上课前咱们花十分钟想想：只有锤子，真的够吗？

## 一、下节课（哦不，就是下节课）要解决什么问题？

你试试跟我们的 Agent 说"帮我看看 loop.py 前十行写了啥"。它当然能干——拼一条 `head -10 loop.py` 交给 bash 就完了。但这里有个微妙的别扭：**读文件、写文件、找文件这些事，本来就是干干净净的独立操作，为什么非要绕道 shell 命令？**

绕道有三个坏处。一是**慢**：每读一个文件都要开一个子进程；二是**脆**：不同系统的 shell 语法不一样，文件名里带个空格就可能翻车；三是**笨**：模型得先"会 shell"才能干活，可读文件这件事根本不需要 shell 知识。所以下节课我们要给 Agent 配一个正经工具箱：`read_file`、`write_file`、`edit_file`、`glob` 四件新工具，加上原有的 bash，凑齐五件套。

## 二、这里有个漂亮的悬念

工具从 1 个变 5 个，你觉得 `agent_loop` 要改多少行？

答案揭晓：**只改一行**。上节课循环里写死了 `run_bash(...)`，下节课我们把这行换成查字典——对，就是 Python 里最普通的字典：`TOOL_HANDLERS = {"bash": run_bash, "read_file": run_read, ...}`。模型要哪个工具，循环就拿工具名去字典里查对应的函数来执行。这个手法叫**查表分发**，是编程里对付"同类事情越来越多"的老方子。以后第 14 课接 MCP 外部工具时，你会发现新工具还是往这张表里登记——表会长大，循环永远那副样子。

## 三、课前小知识

- **glob** 是个老行话，指用通配符找文件：`*.py` 是"所有 py 文件"，`**/*.txt` 里的两个星号表示"把子目录翻个底朝天"。它是 shell 里的老朋友，我们把它包装成独立工具。
- **一次多张单子**：模型的回复是个内容块列表（第 1 课的伏笔还记得吗），所以它完全可以一次回两张调用单："我先 glob 找文件，**同时**跑 wc 数行数"。两张单子怎么跟两个结果配对不搞混？靠上节课讲的 `tool_use_id` 回执编号——下节课测试里你会亲眼看到。
- **安全边界**：给模型 write_file 这种工具，等于把仓库钥匙交给它。我们会在工具箱里埋一个 `safe_path` 小卫兵：所有路径必须待在工作区内，想写 `../../etc/passwd` 这种越界路径直接报错。更完整的门禁系统是第 3 课的主题，这里先垫块砖。
