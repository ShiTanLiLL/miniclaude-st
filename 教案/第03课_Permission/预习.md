# 第 3 课预习 · 自由太危险，给 Agent 装个刹车

> 上节课我们把仓库钥匙（write_file）交给了模型。睡觉前你有没有想过：它半夜要是抽风想改 /etc/passwd 怎么办？

## 一、下节课要解决什么问题？

现在的 Agent 是个"拿到授权就直接执行"的老实人：模型出单，代码照办，中间没有任何人拦一道。绝大多数时候这没问题——但 Agent 的行为本质上依赖模型的一次次"判断"，而模型是会犯错的：它可能误判路径、被奇怪的指令带偏、或者干脆那天状态不好输出了个危险命令。**执行权一旦交出去就没有回头路**的系统，在真实世界是不可用的。

所以下节课我们装刹车，而且是**三道闸**：

1. **死名单**——`rm -rf /`、`sudo` 这种一听就不是好话的，直接拒，没商量；
2. **规则匹配**——路径越界、破坏性命令这种"看情况定危险"的，按规则识别出来；
3. **用户确认**——前面两道都拿不准的，程序停下来问你："Allow? [y/N]"。

三道闸串成一条流水线，站在"模型出单"和"真的执行"之间。下课后你的 Agent 第一次拥有了"拒绝的能力"——这听起来像倒退，其实是任何生产级 Agent 的及格线。

## 二、三个课前小知识

- **正则表达式**（下节课会见到一个）：一种"描述字符串长相"的迷你语言。比如我们要判断"rm 是不是真的作为一条命令出现"，而不是"字符串里含 r 和 m"——`echo firm` 里也有 "rm" 两个字母，但它不是命令。正则就是干这个精细活儿的。看不懂没关系，课上我带你逐个符号拆。
- **白名单与黑名单**：死名单是黑名单思路（列出禁止的），规则表是"黑名单+人工复核"的混合。真实安全系统更偏白名单（默认禁止、列出允许），我们课程里两者都会聊到。
- **input() 函数**：Python 标准库里"程序停下来等用户敲键盘"的方法。第三道闸就是靠它把控制权交还给人——这也是下节课测试里有点意思的地方：测试的时候可没有人真的敲键盘，我们得"假装"有个用户（又是 monkeypatch 的活儿）。

## 三、一个值得先想清楚的问题

被拒绝的操作，程序该怎么处理？选项 A：抛异常终止整个程序。选项 B：把"被拒绝了，原因是……"作为 tool_result 交回给模型，让它自己换条路。

下节课你会看到我们选了 B。想一下为什么 B 更符合 Agent 的气质？（提示：模型是司机，司机被交警拦下后，正常反应是换条路继续开，而不是当场熄火。）

好了，进正课吧。
