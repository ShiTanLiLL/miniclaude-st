# 第 1 课预习 · 在循环开始之前

> 同学，上课前先别急着碰代码。泡杯茶，我们聊十分钟天，把三个"为什么"聊明白，正课时你会轻松很多。

## 一、今天要解决什么问题？

你平时跟 ChatGPT、Claude 这类聊天模型说话，是什么感觉？它**很会说**——你问"当前目录有几个 Python 文件"，它会告诉你"可以运行 `ls *.py | wc -l` 来查看"。

注意到了吗？它只**告诉你怎么做**，从来不**替你做**。你还得自己复制命令、自己敲回车、自己把结果贴回去问它。它像一个被关在玻璃房里的超级顾问：看得见问题，摸不着键盘。

今天这节课，我们要给这位顾问**开一个窗口**：让他说"跑这条命令"的时候，有一个小程序真的替他去跑，再把结果念给他听。这件事一旦打通，"聊天机器人"就变成了"干活的人"——这就是 **Agent** 这個词最朴素的意思。

## 二、三个课前小知识

### 1. 调一次大模型 API，到底是什么样？

类比：你给一位远程同事发工单。工单上有：**你是谁**（system 提示词）、**之前聊了什么**（messages 历史记录）、**你有哪些工具可用**（tools 清单）。他回你一段内容。

技术上就是一个函数调用：`client.messages.create(model=..., system=..., messages=..., tools=...)`。模型回给你的东西叫 **content blocks（内容块）** 的列表——注意，是"列表"哦，因为一次回复里可以混着好几样东西：一段文字、一张工具调用单，甚至好几张调用单。这是今天的伏笔，先记住"回复是一个列表"就好。

### 2. 模型又不能碰你的电脑，它怎么"动手"？

它确实碰不到——它跑在云端的机房里。所以"动手"其实是一场角色扮演：

- 我们先在工单里附一份**工具说明书**："你有一个 bash 工具，输入是一个字符串 command"；
- 模型想动手时，就在回复里夹一张**工具调用单**（术语叫 `tool_use`）：`我要用 bash，命令是 ls`；
- 我们本地的代码看到单子，**替他执行**，把输出包成一个**工具结果**（术语叫 `tool_result`），作为新的一轮消息塞回历史记录；
- 然后再次调用模型——他看到结果，决定接着干活还是收工。

一句话：**模型出嘴，程序出手**。

### 3. 那什么时候停下来？

这是个很妙的设计，妙到近乎偷懒：**我们不停，让模型自己停**。只要他的回复里一张调用单都没有（纯说话），就说明他认为事情做完了，循环结束。你以后学到的所有 Agent——包括 Claude Code 本尊——都是这么停的。

顺便剧透一下今天的主角，五行伪代码：

```python
while True:
    response = 调用模型(历史记录, 工具清单)
    if 回复里没有工具调用单: 收工
    执行每一张单子，结果塞回历史记录
```

整个项目 18 课，改的永远是循环**外面**挂的东西，这个循环本身几乎不再变。
