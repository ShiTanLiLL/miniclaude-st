# 第 6 课预习 · 会干活的 Agent，还需要一个"分身"

> 上节课的清单治好了"步骤漂移"。但这周老师又发现了新病灶，先听故事。

## 一、下节课要解决什么问题？

老师让 Agent 干一件正经任务："检查一下这三个模块的函数命名风格是否一致，不一致的列出来"。它的第一步是搜代码——然后就陷进去了：grep 这个文件、翻那个文件、再看一眼别的……等它终于搜完，聊天记录里已经堆了四十多条中间结果。回头要写总结的时候，它对着满屏的搜索残渣，把自己最初的任务要求都翻不到了。

这个病叫**上下文污染**：干脏活的过程垃圾，淹没了主任务的思考。注意，它跟上节课的"步骤漂移"不同——清单能管住"做没做齐"，管不住"过程垃圾把思路挤没了"。

下节课的药方很优雅：**派分身**。主 Agent 把脏活连同指令打包成一张 `task` 工具单；分身（subagent）在一段**全新的空白聊天记录**里自己跑循环，翻一百个文件也好，主 Agent 的记录里干干净净；分身干完，只把**最后一段文字结论**作为工具结果带回。过程留在分身的世界，结论回到主任务。

## 二、三个课前小知识

- **函数是一等公民**（再见面了）：上上次它让工具能塞进字典，这次它让"整个循环"能塞进一个函数里。`run_subagent(prompt)` 本质上就是把 `agent_loop` 的形状抄进一个函数、给它一个全新的 messages 起点、再把返回值收窄成一段文本。你会看到"同一个循环形状，跑在两个嵌套层级"。
- **递归的边界**：分身拿到的是基础工具（bash、文件五件套、todo），**唯独没有 task 本身**。为什么？想想如果分身也有 task——它可以再派分身，分身再派分身……没有边界的递归会吃光你的 API 额度。给递归划一条明确的线，是所有嵌套设计的必修课。
- **30 轮上限**：分身的循环套了 `for _ in range(30)`。它要是钻进牛角尖出不来（模型偶尔会），30 轮后强制收工，带回一句"我没能在轮数内完成"。**循环必须有出口，尤其是你不在旁边盯着的循环**。

## 三、课前小任务

想一件你日常会"外包"的小事：查快递、整理房间角落、翻聊天记录找某个链接。外包时你给对方的指令要说到什么程度，才能"不用中途来问你"？这个"打包指令"的质量，就是下节课 task 工具单里 prompt 的质量——好分身从好指令开始。

好，进正课吧。
